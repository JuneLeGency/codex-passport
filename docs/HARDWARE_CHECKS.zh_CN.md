# Passport 硬件能力与实测

2026-09-12，在同一台 ESP32-C3 AI Passport 上运行独立编写的临时检测程序。
官方能力依据：[FoloToy 硬件能力表](https://github.com/folotoy/ai-passport#hardware-capability-contract)。
以下是单台设备的功能检查，不能代替批次验证或电气校准。

| 能力 | 本次观察 | 对当前应用的价值 |
| --- | --- | --- |
| 扬声器 / ES8311 | 三次短提示音播放完成，用户确认听到声音；后两次播放前后空闲堆一致 | 新待回复/待批准短响，至少间隔两分钟；双击 OK 静音 |
| 麦克风 | 预热后回采自身 1kHz 测试音，该频率 RMS 从背景约 5.0 增至 34.7；只计算数值，不保存录音 | 将来可评估按键录音；当前通知应用不启用麦克风 |
| Wi-Fi | 被动扫描、连接用户指定的 2.4GHz 网络、DHCP 获取地址、连接局域网中继 TCP 端口均通过；结束后断开并释放 | 0.3.0 已加入手机配网、认证 HTTP 同步和失败回退，实际回执通过 |
| CW2017 电量计 | 三次读取约 96%、4109mV | 电量显示；0.3.0 在低电量时限制背光与亮屏时间，未测续航收益 |
| 背光 | 15% / 55% / 0% / 55% 对应 PWM 占空值 153 / 562 / 0 / 562 | 夜间亮度与自动熄屏；未测实际亮度 |
| NVS | 独立测试命名空间写入固定校验值，重启后读回一致，随后清除测试命名空间 | 静音等偏好可以重启保留；避免每次同步都写 Flash |

Wi-Fi 首次尝试使用了随后被用户更正的网络名称，该结果不计入验收。
检测程序的联网事件日志曾触发默认事件任务栈溢出；降低临时检测的系统日志级别后，完成上述连接与 TCP 检查。
麦克风初始采样受上电影响；表格采用预热后的指定频率测量，不代表语音识别或录音质量验证。

浅睡测试导致 USB 调试断开，重新接入又触发芯片复位，未获得可靠的休眠唤醒验收结果。
按用户要求，不继续做续航、无线距离测试。本应用采用 Wi-Fi/BLE 互斥切换；没有测试两者并发、远程升级或外网 WireGuard。

临时程序只写应用分区，不擦除原有配对、cardid 或 Recovery。
Wi-Fi 凭据仅进入被忽略的本地临时测试文件和临时固件，连接配置只使用 RAM；不进入开源代码、发布固件或此文档。
检测结束后恢复通知固件。

## 优先利用的能力

1. 短提示音与可保存的静音设置：让新增提醒容易被察觉，控制重复响铃。
2. 背光和电量：以可读性为前提改善夜间使用；是否延长续航需另测。
3. Wi-Fi：0.3.0 提供可选直连，手机完成配网，失败后保持 BLE 路径，需手动重新启用。

麦克风暂不加入日常功能，保持当前只看进展的定位。
官方 BSP 未提供触控、震动马达或姿态传感器接口，不按已有能力设计相关交互。

## 0.3.0 通知应用集成验收

- 手机设置弹窗通过已配对 BLE 下发网络；Passport 通过 Wi-Fi 提交了认证 API 同步回执，手机显示实际直连成功。
- 重启后 Wi-Fi 自动恢复，静音、音量、亮度和熄屏设置保持。Wi-Fi 同步观察到约 73 KB 空闲堆；这是功能测试中的瞬时值，不代表长期稳定性或续航。
- 通过 Wi-Fi 修改屏幕设置，再恢复原设置，均有匹配命令回执。
- Wi-Fi → 电脑 BLE → 手机 BLE → 已保存 Wi-Fi → 关闭 Wi-Fi 回手机，各阶段均有临时测试事件的设备回执，随后移除测试事件。没有重新输入蓝牙验证码。
- 临时配置不可达的局域网应用端口，设备结束失败直连并恢复手机 BLE。恢复正确中继后 Wi-Fi 再次同步；最后返回手机 BLE。
- 0.3.0 发行固件本身不包含个人 Wi-Fi 凭据。配网后设备将配置保存在 NVS；可从手机「忘记 Passport 的 Wi-Fi」删除。手机偏好和事件库不保存网络密码。
